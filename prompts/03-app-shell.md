# 03 — App shell

## Goal

Build the persistent shell that wraps every route: the announcement bar, the header, the footer, the
Rail with its scroll-progress paint, and the Ask bar with its typing placeholder and focus
expansion. After this prompt, `/` renders a complete, scrollable, keyboard-operable page frame with
nothing in the middle of it — the fourteen content sections of §8 land in prompts 04+.

Scope was chosen by the user at approval time: **full shell including the Ask bar** (the third of
three options offered), and **in-page anchors only** for the header nav.

This prompt delivers the second of §7.3's three orchestrated moments (rail progress). The hero load
belongs to prompt 04; the panel vignettes to the capability-section prompts.

## Decisions and assumptions

### 1. `@gsap/react` must be installed

§7 requires every animation to go through `useGSAP`, and the package is not in `package.json`. Run
`npm install @gsap/react`. ScrollTrigger ships inside the `gsap` package and needs no extra install.
This is the only dependency added.

### 2. `motion` stays installed and unused — flagged, not resolved

§15 lists "remove `motion` or document its use" as an open decision. This prompt does not resolve it;
it adds no `motion` import. Raise it again when the last GSAP surface lands.

### 3. The Rail is split in two, so it works without JavaScript

`components/layout/rail.tsx` (client) draws the line and owns the scrub. `components/layout/
rail-station.tsx` (server) is a node plus a Utility-face label that a **section renders inside
itself**. Sections therefore self-register their stations — no DOM measuring, no `[data-station]`
querying, no `ScrollTrigger.refresh()` after markers appear, and the markers are present in the HTML
with JS disabled (§12).

Rejected: a single client Rail that measures section positions and renders markers itself. It would
have to re-measure on every font load and content change, and would render nothing without JS.

### 4. Rail geometry gets two new tokens

`--rail-inset` is currently defined and used nowhere. Replace it with:

- `--rail-x` — distance from the content shell's outer edge to the line: `var(--gutter)` at ≥640px,
  `4px` below (§6.4's "extreme left gutter" on mobile).
- `--rail-gap` — `clamp(24px, 4vw, 56px)`, the space between the line and the content that hangs off
  it. Sections in later prompts indent their content by this to align to the rail.

Both are consumed through `@utility` blocks, never as arbitrary values in TSX (§13).

### 5. The progress paint is exact, not approximate

A ScrollTrigger on `<main>` with `start: "top center"`, `end: "bottom center"`, `scrub: true`,
scrubbing `scaleY` 0 → 1 on the paint element (`transform-origin: top`) puts the paint's tip exactly
at the viewport's vertical midpoint at every scroll position: at progress *p* the paint is
`p × mainHeight` tall, and the midpoint sits `p × mainHeight` into `<main>`. That is §6.4's
"travelled portion is visibly behind you", with no per-frame measurement and transform-only work
(§7.1).

### 6. The Ask bar expands without animating layout

§7.1 forbids animating `height`. The suggested-question chip row is therefore **absolutely
positioned above the field, out of flow**, so revealing it changes no layout and the reveal is a pure
`opacity` + `y` tween. At rest the row carries `inert`, which removes its buttons from the tab order
and from the accessibility tree in one attribute (React 19 supports it) — no `tabIndex={-1}` +
`aria-hidden` pair to keep in sync.

### 7. The Ask bar uses a bare `<input>`, not `components/ui/input.tsx`

§10 says compose primitives before hand-rolling. The Ask bar field needs no border, no ring, no
background, a 56px pill height, and the placeholder written imperatively — which means overriding
every line of the primitive's class string. That is forking by `className`, not composing. A plain
`<input>` inside the bar shell is smaller and more honest. The send button and the chips **do** use
`components/ui/button.tsx` (`variant="pill"` and a new `chip` variant added via `cva` in that file,
per §10's "add a variant via cva in that file").

### 8. The online dot is `--ink`, not green

§8.1 says "an online dot appears"; the reference's is green. §6's governing rule is that no coloured
icon exists on the page chrome, and this dot is chrome. It renders as a 6px `--ink` circle. If a
green dot is wanted, it is a deliberate exception to §6 and needs its own approval.

### 9. Send-button state follows §8.1, not the reference

§8.1: on focus the send button goes solid `--ink`. The reference additionally reverts it to pale when
you clear the field while still focused. That nuance is not in §8.1 and produces a three-state
machine for no gain. Rule implemented: **solid `--ink` when the field is focused or non-empty; pale
`--surface` otherwise.**

### 10. The send button is inert, and says so

Per §8.1 and §15, post-submit UI is undesigned. The form's `onSubmit` calls `preventDefault()` and
does nothing else. The button is **not** `disabled` — a disabled control is a lie about a feature
that is coming and drops it from the tab order, breaking §12's full-keyboard requirement. It is
focusable, activatable, and inert. This is stated here rather than hidden.

### 11. Announcement-bar copy is a product statement, not a metric

§11.2 requires this line to be true. "50+ languages" is a metric we cannot stand behind, so it is not
used. The line restates §1's own product description: *"Glidda runs your guide in any language, around
the clock."* No fixture, no `placeholder: true`, no PLACEHOLDER chip — this prompt creates no
fabricated proof at all.

### 12. Header nav is three in-page anchors; no mobile menu

Per the user's answer: wordmark · `Answers` · `Demos` · `FAQ` · `[Start a guide]`. The reference's
dropdown and "Sign in" link are dropped because §1 puts those routes out of scope and shipping
`href="#"` would be a dead link. Below `md` the anchors are hidden and only the wordmark and the pill
remain — a sheet menu for three same-page anchors on a page the user is already scrolling is
overbuilding (§16.1).

### 13. `app/page.tsx` gets temporary section stubs

§9 says `page.tsx` composes sections and nothing else, but no sections exist yet, and a rail with
nothing to span and an Ask bar with nothing to scroll past cannot be reviewed. `page.tsx` therefore
renders three minimal stub `<section>` elements carrying the anchor ids and a `RailStation`, each
marked with a `TODO(04+)` comment naming the prompt that replaces it. They contain one headline and
one paragraph of real copy and no layout maths. **Every stub is deleted as its real section lands.**

### 14. The typewriter is a hook, not a component

§9's layout anticipates `components/motion/typewriter.tsx`. What this actually is is a hook that
writes to an input's `placeholder` property — it renders nothing, so it does not belong in
`components/`. It ships as `hooks/use-typewriter-placeholder.ts`. Noted as a deliberate, minor
departure from §9's file list.

### 15. GSAP registration happens once, in a client module

`lib/gsap/register.ts` — `"use client"`, imports `gsap`, `ScrollTrigger`, `useGSAP`, calls
`gsap.registerPlugin(useGSAP, ScrollTrigger)` at module scope, exports `gsap` and `ScrollTrigger`.
Every animated component imports from there and never calls `registerPlugin` itself (§7.1).
`lib/gsap/motion.ts` holds the shared duration and ease constants so no duration literal is repeated
(§13).

### `components/layout/rail.tsx` — client

Renders inside `<main>`, which must be `relative`. Markup: an absolutely positioned `content-shell`
wrapper with `pointer-events-none`, containing `rail-track` and, inside it, `rail-paint`. The whole
component is `aria-hidden` (§12 — decorative).

```tsx
useGSAP(() => {
  const mm = gsap.matchMedia()
  mm.add({ motion: "(prefers-reduced-motion: no-preference)",
           reduced: "(prefers-reduced-motion: reduce)" }, (ctx) => {
    if (ctx.conditions?.reduced) { gsap.set(paintRef.current, { scaleY: 1 }); return }
    gsap.to(paintRef.current, {
      scaleY: 1, ease: "none",
      scrollTrigger: { trigger: mainEl, start: "top center", end: "bottom center", scrub: true },
    })
  })
  return () => mm.revert()
}, { scope: rootRef })
```

- `ease: "none"` — a scrubbed tween must map linearly to scroll.
- `scrub` only; never paired with `toggleActions` (skill: "scrub wins", do not use both).
- The trigger is the parent `<main>`, reached via `rootRef.current.parentElement`, not a selector —
  the Rail must not know a class name that lives in `layout.tsx`.
- `markers: false` in production. If markers are used while building, remove them before the checks.
- Cleanup is `mm.revert()` inside `useGSAP`, which also kills the ScrollTrigger (§7.1).

### `components/layout/rail-station.tsx` — server

Props: `{ label: string }`. Absolutely positioned at `left: var(--rail-x)`, a `rail-node` square
plus a `type-utility` label in `--rail-muted` offset to its right. Label hidden below `640px`, node
kept (§6.4). `aria-hidden` — the label duplicates the section's own heading and would double-announce.

### `components/ask/ask-bar.tsx` — client

Fixed, bottom centre, `z-index: var(--z-ask)`, `bottom: calc(env(safe-area-inset-bottom, 0px) +
var(--gutter))`. Width `min(560px, 100% - 2 × var(--gutter))`. `id="ask"` so the header CTA and
footer links land on it, plus `anchor-offset`.

Shell: `--paper` background, `rounded-pill`, `--ask-bar-height` tall, `shadow-ask` — the one shadow
permitted on the page (§6.3). A `<form>` inside with a bare `<input>` (decision 7) and the send
button.

**State** — three booleans at most: `focused`, `hasValue`. Expanded ⇔ focus is anywhere inside the
bar. Track with `onFocusCapture` / `onBlurCapture` on the shell, comparing
`event.relatedTarget` against `shellRef.current.contains(...)` so moving focus from the input to a
chip does not collapse it.

**Rest state** — placeholder driven by `useTypewriterPlaceholder`; send button `--surface` fill with
an `--ink` `ArrowUp`.

**Focused state** — chips row fades and rises in (`opacity` + `y: 8 → 0`, `DURATION.micro`,
`EASE.entrance`), `inert` removed; placeholder switches to the static `focusPlaceholder` and the
typewriter timeline is paused; the online dot appears at the field's right; the send button goes
solid `--ink` with a `--paper` arrow (decision 9).

**Keyboard** (§8.1, §12): Tab reaches the input with a visible focus ring on the **shell** (the input
itself has no ring — the ring must trace the pill, not a rectangle inside it); `Escape` blurs the
input and collapses; chips are real `<button>`s in the tab order when expanded; `Enter` submits the
form, which `preventDefault()`s and does nothing (decision 10).

**Mobile** (<640px): full width minus gutters; the chip row does not render at all; the bar sits
above `env(safe-area-inset-bottom)` so it does not fight the on-screen keyboard.

### `components/ask/ask-chips.tsx` — client

Absolutely positioned above the shell, `bottom: calc(100% + 8px)`, horizontally scrollable
(`overflow-x-auto`, no horizontal *page* scroll — §12). Three `<Button variant="chip">`s; clicking one
writes its text into the input, keeps focus in the bar, and does not submit.

### `components/ui/button.tsx`

Add one `chip` variant via the existing `cva` block, in place (§10):
`rounded-pill hairline bg-paper text-ink text-small px-4 h-8 hover:bg-surface`, composed with
`focusRing` and `disabledState` like the other two Glidda variants. No new wrapper component.

### `hooks/use-typewriter-placeholder.ts` — client

`useTypewriterPlaceholder(inputRef, { questions, paused, staticText })`.

- Builds **one** repeating `gsap.timeline({ repeat: -1 })` inside `useGSAP`.
- Per question: tween a proxy `{ n: 0 }` → `{ n: text.length }` with `ease: "none"` and
  `snap: { n: 1 }`, writing `inputRef.current.placeholder = text.slice(0, n)` in `onUpdate`; hold;
  then the same tween in reverse to delete. Writing the DOM property directly avoids a React
  re-render per character.
- Full cycle sits inside §7.1's 8–20s ambient window.
- `paused` (the bar is focused) calls `timeline.pause()` and writes `staticText`.
- Reduced motion (`gsap.matchMedia`): no timeline at all; the placeholder is set once to
  `ask.reducedMotionPlaceholder` (§7.2).
- Guard `inputRef.current` on every write — the timeline outlives no unmount thanks to `useGSAP`,
  but the ref can still be null on the first frame.

## Motion spec

| What | Trigger | Duration | Ease | Reduced motion |
| --- | --- | --- | --- | --- |
| Rail progress paint (`scaleY` 0→1) | ScrollTrigger scrub on `<main>`, `top center` → `bottom center` | scrubbed | `none` | `scaleY(1)` set instantly |
| Ask placeholder typewriter | mount, `repeat: -1`, pauses on focus | ~15s cycle | `none` per char, snapped | no timeline; one static string |
| Chip row reveal (`opacity`, `y` 8→0) | focus within the bar | `DURATION.micro` | `EASE.entrance` | opacity only, no `y` |
| Send button fill | focus / value | `--duration-micro` | `--ease-entrance` | unchanged (colour only) |
| Announcement arrow | hover / focus-visible | `--duration-micro` | `--ease-entrance` | unchanged (colour + 4px, below the reduced-motion threshold) |
| Header anchor hover surface | hover | `--duration-micro` | `--ease-entrance` | unchanged |

Transform and opacity only, everywhere. Nothing here is a fourth orchestrated moment: the rail is
§7.3 #2, and the typewriter is mandated by §8.1 as the Ask bar's defining behaviour rather than added
decoration. Everything else in the table is a ≤200ms hover or state change.

## Accessibility requirements

- Skip link first in the body, visible on focus.
- One `h1`; stub sections use `h2` in order.
- `<nav aria-label="Page sections">` in the header, `<nav aria-label="Footer">` in the footer.
- Rail and stations `aria-hidden` (decorative, §12). Everything conveying information is not.
- Visible focus on every interactive element via `focusRing`; the Ask bar's ring traces the pill.
- Full keyboard operation: Tab reaches announcement bar → header anchors → CTA → page → footer links
  → Ask bar input → chips → send. `Escape` collapses the Ask bar.
- Chips are `inert` while collapsed — out of the tab order and out of the a11y tree.
- `--rail-muted` is the only muted tone; `--rail` and `--signal` carry no text.
- No horizontal page scroll at 360px; the chip row scrolls inside itself.
- The page reads and navigates with JS disabled: bar, header, footer, rail line, station markers, and
  the Ask bar's markup all render; only the paint, the typewriter, and the chip reveal are absent.

## Acceptance criteria

1. `/` renders announcement bar, header, three stub sections, footer, and a fixed Ask bar, in that
   order, with no horizontal scroll at 360 / 768 / 1024 / 1440.
2. The rail line spans the full height of `<main>` and its `--ink` paint tip tracks the viewport's
   vertical midpoint through a full scroll.
3. Station markers render in the initial HTML (verify with JS disabled).
4. The Ask bar's placeholder types and deletes through the three questions on a loop and pauses on
   focus.
5. Focusing the Ask bar reveals the chip row with no layout shift anywhere on the page.
6. `Escape` collapses the bar; chips are unreachable by Tab while collapsed and reachable while
   expanded; `Enter` does nothing visible and throws nothing.
7. `prefers-reduced-motion: reduce`: rail fully painted immediately, one static placeholder, chips
   fade with no rise, nothing loops.
8. Zero hex literals and zero arbitrary values in `app/` and `components/`.

10. `npm run typecheck`, `npm run lint`, and `npm run build` all pass.
11. `components/ui/` shows exactly one changed file (`button.tsx`, one added variant).
12. No `href="#"` in the codebase.
